# 腾讯 AI Desk 鸿蒙接入核查

核查日期：2026-10-05。当前组件包装 Tencent AI Desk，Android 的 `aideskcustomer` 与 iOS 的 `TencentCloudAIDeskCustomer`；不是智齿 Sobot，不能将另一服务的 AppKey/会话/页面当作同一腾讯能力。

本轮已在线核查，不能再把“腾讯客服不支持鸿蒙”当作结论：

- 官方 [uni-app 接入](https://cloud.tencent.com/document/product/679/116622) 明确 `ai-desk-customer-uniapp >= 1.5.11` 可将 Vue3 项目打包鸿蒙应用。它提供 Vue 客服组件，依赖 uni-app runtime；没有提供能直接由现有 ArkUI/Kuikly Native 宿主导入的客服 HAR/View。
- 官方 [无 UI 用户端协议](https://cloud.tencent.com/document/product/269/96058) 公开 IM C2C 自定义消息方案，激活服务流为 `customerServicePlugin=0, src="7"`，要求 online-only 发送，并由企业开通/配置客服咨询入口。除文本外还包含评价、分支、表单、卡片、流式消息、多轮任务、转人工和退出协议。用普通 IM 聊天页不能代替这些能力或现有厂商客服 UI。
- 官方 [Harmony Chat 接入](https://cloud.tencent.com/document/product/269/125128) 证明 ArkUI IM 能力可用，不证明已包装完整 AI Desk 用户页面或 `initWithProfile/getCustomerServiceViewController/unInit` 等价入口。
- 对两个推测的 OHPM 名 `@tencentcloud/aideskcustomer` 与 `@tencentcloud/ai-desk-customer` 查询均为 HTTP 404。这里只证明这两个名字未找到，不能推断腾讯所有私有分发渠道都没有 SDK。

本轮未取得可编译并消费的原厂 ArkUI AI Desk HAR 和相应 API。现有 Kotlin/Swift 组件继续包装原厂完整 UI，鸿蒙仍未实装，不返回空成功。要保持这个契约，需要腾讯提供当前原生鸿蒙包及账号/资料/页面关闭/reset 接口；uni-app 可作为独立宿主路线，但不能直接冒充 Native HAR。

按公开 IM 协议自建全部客服 UI 是另一条可开发路线，协议已公开，不列为“协议不存在”的阻断。它需要企业实际启用的咨询入口、流程类型与账号测试契约，并完整覆盖上列用户流程；本轮没有这些业务配置或真实账号结果，不能把只实现 `src=7`/文本收发的 demo 发布为完整客服适配。当前只报告现有 Native 契约的缺失与已核验的可用路线，不宣称整个鸿蒙平台无法实现腾讯客服。
